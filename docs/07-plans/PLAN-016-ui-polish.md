## 1. Problem & goal

M1 works, but it does not yet feel finished next to Linear. The audit found three kinds of gap:

- **Visible bugs:** default purple breadcrumb links, three focus rings on one text field, a ring that leaks into the command menu, and an issue title that sits off the description's left edge.
- **Missing craft:** no layering (content is painted straight on the app layer), a 1 px line under every row, flat type weights, single-blur shadows, overlays that vanish instead of fading out, and states (hover, focus, selection) that look alike.
- **Missing patterns:** a command menu with a heavy backdrop, keyboard pickers that open as popovers, an issue page that reads like a form, and settings pages with no shared layout.

The goal is to adopt Linear's **craft** while keeping Surface's own identity (D-a): its teal accent, palette and logo stay. Contrast stays at AA, tested. Where Linear is weaker, Surface keeps its edge: focus that is distinct from hover (D-f), tested contrast, reduced motion, the command-menu footer of key hints.

**Not in scope** (product work, not polish; the audit lists them so this plan does not assume them): view tabs, filter and display controls in the header, multi-select with `X` and its bulk bar, and peek. They belong to M2 (SPEC-020 to SPEC-023). This plan only readies the tokens they will use.

> **As built (2026-11-25, `p016-s2-overlays`):**
>
> - **Exits:** Dialog (+ backdrop and the discard alert dialog), Menu, ContextMenu and submenus, Popover, Tooltip and Toast have `[data-state='closed']` rules: `exit var(--dur-exit) var(--ease-in) forwards`, opacity plus `--motion-scale` (Dialog and Toast: `--motion-shift` too). The shift is the existing `--motion-shift` (4 px), not the plan's 2 px, so the token stays single; reduced motion leaves opacity. Menu and Popover enter from the side they open to (`data-side`, four `enter-from-*` keyframes).
> - **Focus and the layer stack:** Radix `onCloseAutoFocus` only fires after the exit ends, so `overlays/layer.tsx` now returns focus when the close _starts_: Dialog from a passive effect on `open` (after Radix's trap is off), Menu and Popover from a `MutationObserver` on the content's `data-state` (one microtask). Focus that already moved elsewhere (a dialog opened from an item, a click outside) is left alone, and the later `onCloseAutoFocus` is suppressed. A fading menu or popover leaves the layer stack at once (Esc and `topLayer` ignore it) and re-registers if it reopens mid-fade. `Dialog` `onClosed` still fires after the exit (about 80 ms later). The discard alert skips the early restore when discarding.
> - **Toast:** `ToastRegion` keeps a dismissed toast mounted with `open={false}` until `animationend` (400 ms fallback). A toast replaced in place (same id) swaps without a fade. A fourth toast can show for 80 ms while the third leaves.
> - **Styling:** `--radius-lg` on menus, popovers and toasts; tooltip 28 px min height, `--radius-md`; menu and picker items 30 px (new token `--menu-item-height`) at weight 450 with highlight motion (in 0, out 150); menu separator is a hairline; submenus use e2; kbd caps weight 450, hairline border, `--radius-kbd`. PropertyPicker search: no ring, hairline underline. The command-menu input had its ring removed in S0 (checked).
> - **Tests:** `ui/test/overlay-exit.test.tsx` (each overlay goes through `closed` and unmounts on `animationend`; focus is back on the trigger while the dialog and menu are still fading; a fading menu is not the top layer) and `ui/test/keyframes-motion.test.ts` (keyframes move only through `--motion-*`; each overlay has an exit on `--dur-exit` and `--ease-in`). jsdom only knows the animation because the test injects a stylesheet. `pnpm check` green. Storybook story tests and visual baselines were not run (not in the gate; baselines will differ).
> - **Review round (2026-11-25):** a fading overlay is now treated as closed for everything except painting: `pointer-events: none` in CSS, `inert` on the node, off the layer stack, focus returned and the page's `aria-hidden` lifted from the return target (chosen over re-focusing after unmount, which would steal focus the user moved in 80 ms). Dialog content is keyed per opening, so a reopen mid-fade mounts afresh (and focuses); menus and popovers refocus their content on a mid-fade reopen. Focus ownership walks nested layers (submenus, a menu inside a dialog) through the return-target chain. The discard question has no exit. `Dialog` `onClosed` now fires as the close starts (after focus returns), so the command menu runs its command without waiting for the exit, and its body stays rendered while fading. **Known limit:** Radix keeps the fading layer in its dismiss stack, so Esc within 80 ms does not reach the dialog underneath. Body `pointer-events: none` from a modal dialog also lasts through the fade.
> - **Known gap:** when a dialog opens while another is still fading (command menu to composer), the reveal of `aria-hidden` can miss the second close because the aria-hidden library's marker is not set again; focus then sits on an aria-hidden trigger for the 80 ms, as before the reveal. A dialog reopened mid-fade ignores the old content's late `onCloseAutoFocus`.
> - **For S5 / S8:** the command-menu dialog now exits too, and the focus return is early, so S5's "Esc returns focus to the row" works with the exit running. S8's toast exit is done here. Not done: no headless by-hand capture was taken.

## 6. Risks & mitigations

| Risk                                                                                                                                                                                                                                     | Mitigation                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Exit animations vs the overlay manager.** Radix Presence keeps an element mounted until `animationend`. jsdom has no animations, so tests see an instant unmount, and a real browser could show stacking or focus bugs the tests miss. | Focus restoration stays synchronous (the manager does it, not Presence). Test the closing `data-state` in jsdom, and check stacking and focus with exits on by hand in a headless run. `overlay-manager.test.ts` must stay green. Reduced motion keeps opacity only. |
| **0.5 px hairlines on 1x screens.** A half pixel renders as nothing or as a blurry 1 px line.                                                                                                                                            | `--hairline` falls back to 1 px under `min-resolution: 2dppx`. `--border-hairline` is slightly stronger. Decorative borders are exempt from §2.3, but controls keep 1 px `--border-control`. Check on a 1x monitor by hand.                                          |
| **Row render budget.** 44 px rows with state shadows and transitions could cost more per row, and the list must stay at 60 fps with 10,000 issues (NFR-04).                                                                              | Heights are fixed constants, so the window is arithmetic (SPEC-012 §3.3 item 9).
