### Real-server test entry (D's, was a handoff to A)

**Goal.** `tests/sync-sim` runs the same two properties (AC-2 convergence, AC-3 exactly-once) against the real server: executor, repo, `sync_log`, hub and Postgres. It wraps the server in its `SimServer` interface (`tests/sync-sim/src/server.ts`), the way it wraps sync-client's fake hub today. The tests are `*.int.test.ts` (Postgres). They are not held: the sync property suite is exempt (SPEC-002 D1).

**What D needs from `apps/server`:**

1. **A test-only entry**, for example `@surface/server/testing`. `apps/server` has no `exports` map yet; add one with the `@surface/source` condition like the packages, so `tests/` gets TypeScript source. D will add an additive dependency-cruiser rule so only `tests/` may import it, mirroring `test-doubles-only-in-tests`.
2. **Start, restart, stop** on a database D provides (a URL from your `createTestDatabase()` / template DB, or the entry creates and drops one):
   - `start({ databaseUrl })` builds the server through `startServer` on `127.0.0.1:0` and resolves with its base URL once ready. Config comes from a `Config` object built in code, never from `process.env` (rule 7).
   - `restart()` stops it and starts a new one on the same database. Live sockets close with `1012`, in-flight requests may be lost, and committed rows and `client_mutations` survive. The port may change; D reconnects through its own network.
   - `stop()` shuts it down and closes the pool.
   - Signed-in users (A, 2026-11-07): `resolveActor`, which `startServer` accepts, works today; once PLAN-001 S3 is on `main`, switch to real sessions (`pgAuthStore.createSession` plus `csrfToken(sessionSecret, sessionId)` in `apps/server/src/auth/`), so the properties also cover sign-in cookies and CSRF.
   - Since PLAN-001 S2 a fresh database answers `503 SETUP_REQUIRED` on `/api` and `/sync` until first-run setup is done, so `start` completes setup first (A, via the coordinator, 2026-11-07). A's order: PLAN-001 S3 or PLAN-002 S5 (the user is choosing), then C's current-session endpoint, then this entry.
3. **Signed-in users without the login flow.** Bootstrap and the socket refuse anyone but a signed-in user (Q7, Q9), and sessions arrive in PLAN-001 S3. So give D a way to:
   - create N users who are members of one team, so the debug rows' sync groups are visible to all of them;
   - authenticate each user's requests and socket upgrades, for example a `resolveActor` that maps a test header or cookie to the user.

   A private-team variant (a user outside the team) would be welcome later for AC-11, but is not needed now.
4. **Fixtures and reads:**
   - **Seed** debug items through the executor (`debug.create` as one of the users), so `sync_log` and groups are written by the repo layer (rule 2). No direct table writes.
   - **Read** the current head (the last committed `sync_id`), and `debug_items` with id, title, counter, archived/deleted state and `sync_groups`. Reading from the test database's pool directly is fine.
5. **Timers.** The harness fakes `setTimeout`, `setInterval` and `Date` for the whole process, so an in-process server runs on fake time too.
   - Let the entry set the hub's `pingIntervalMs` and `pongTimeoutMs` (`HubOptions` has them), and turn off the job worker.
   - Say which other server timers matter, such as pool idle and connection timeouts, request timeouts, and the listen retry. D decides on its side which of them run on real time.

**Not needed:** the debug ops beyond `create`, `rename`, `touch` and `delete`; metrics; logs (silent is fine).

**Server bugs** the properties find come back to A as new handoffs here, each with its seed and a shrunk case.

> **As built (2026-11-07, D, branch `p002-s9-server-entry`).** `@surface/server/testing` → `apps/server/test/support/testing.ts`, like sync-client's `/testing` (ADR-0016): outside `src`, so it never reaches the build or the image. `apps/server/package.json` gained an `exports` map (`.` → `dist/main.js` as before, `./testing`). Dependency-cruiser `server-testing-only-in-tests` (additive): nothing in `apps/` or `packages/` imports `apps/server/test/` except the server's own tests (probed from `apps/server/src` and from a package).
> - `startTestServer({ databaseUrl, users })` takes a database not yet set up (one an earlier entry set up is refused, with a message saying so) and starts the server through `startServer(config, { syncFixtures: true })` (A's S3 follow-up) on `127.0.0.1:0`, role `web` (the hub, no job worker, no SMTP), `NODE_ENV=test` (debug operations allowed), config from `loadConfig` on an object (rule 7). It completes first-run setup with a configured setup token, adds the other users through the repo layer as members of the setup's team, and signs each in with a real session and CSRF token: `users[n].cookie` and `.csrfToken` (the Admin keeps setup's session). Its own pool is built with the server's `createPool` (an idle connection that fails is logged, not an uncaught error), and the extra users are written in `transactionRunner`. Clients send no `Origin`: the socket accepts only `http://127.0.0.1`, without the port.
> - `run(user, op, input)` posts to `/api/ops/:name` like a client (session, CSRF, executor, repo). Reads: `head()`, `items()`. `restart()` is `gracefulShutdown` (sockets close with 1012) and a new server on the same database; sessions and rows survive, the port may change (`url`). `stop()` also closes the entry's own pool, even when shutdown fails; a second call does nothing, and `restart()` after it throws. The caller drops the database. `schemaHash` is the fixtures-included hash.
> - **Timers** (item 5): the hub's ping interval and pong timeout keep the protocol defaults (the client uses the same constants, so fake time drives both); `startServer` has no option for them, and none is needed so far. Server timers that run in-process: the hub's ping `setInterval` and pong `setTimeout`, its catch-up drain poll and listen retry (`node:timers/promises`), `gracefulShutdown`'s 10 s drain timeout, the pool's 5 s connect and 30 s idle timeouts (pg's own timers), and `waitForDatabase`'s retry sleeps. Part 2 decides which run on real time.
> - **Tests:** `apps/server/test/testing-entry.int.test.ts` (5): users sign in and run debug operations, and bootstrap reports the fixtures-included hash; a POST without the CSRF token is refused with `CSRF_INVALID` (so sessions are real, not a `resolveActor` bypass); rows and sessions survive a restart; an already set-up database is refused with a clear message; `stop()` twice. `testing-entry.test.ts` (1, unit): `users` must be a whole number of at least 1. Part of the sync property suite, which the hold exempts (SPEC-002 D1).
> - **Not yet possible:** the properties against the real server need `POST /sync/mutate` (PLAN-002 S5, A), which is not on `main`. `tests/sync-sim` will import the entry (a `@surface/server` workspace dev dependency) in part 2.
