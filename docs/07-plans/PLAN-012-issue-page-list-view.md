### S1: Shortcut engine, property commands, availability · L · ✅ Done 2026-11-12
Everything the M1 key map (§3.6) needs from the engine, before any screen binds a key. Behind a stub: the new scopes have no page yet, and the new bindings are registered with commands whose handlers come in S3 to S6 (a command with no handler is simply unavailable, SPEC-005 §5).
- **`whileTyping` per binding** (`apps/web/src/shortcuts/registry.ts`, `engine.ts` `#accepts`): optional field on `ShortcutDefinition`, default as today. The registry refuses to load a text-editing chord (`Mod+Backspace`, `Mod+Delete`, `Mod+Z`, `Mod+Shift+Z`, `Mod+A/C/X/V`, `Mod+←/→/↑/↓`) without `whileTyping: false`.
- **`event.code` rules** (`chord.ts`, `toChord`): match on `event.code` for digits, every chord with `Alt`, and chords with `Shift` and a non-letter; everything else stays on `event.key`. The engine tries `event.key` matches first and `event.code` only if none matched. Plain symbols (`#`, `?`, `[`) stay on `event.key`.
- **Literal `Ctrl`** next to `Mod` in chord parsing, matching and display (`chord.ts`, `help.ts`, and `packages/ui/src/keys.ts` for key labels and `aria-keyshortcuts`). **`platform: 'mac'`** on a binding: the registry drops it elsewhere, and the help overlay hides it.
- **New scopes** `issue-page`, `comment`, `settings-row` in `SCOPES` and the `OVERLAPPING` and `SPECIFICITY` tables (`conflicts.ts`) with the pairs of §3.6. Update `ShortcutProvider.tsx` so a page or component can activate them (the page scopes `issue-page`; the component scopes `comment`, `settings-row` by focus).
- **The M1 key map** added to `registry.ts` and `commands/catalog.ts`: every row of §3.6 owned by this spec (and the rows owned by SPEC-010, 013, 014 and 015 as listed registry entries, so the conflict test runs once). Commands without a handler yet stay unavailable. `Mod+/` joins `?` for the help overlay. Reserved keys (§3.6) are added to the conflict test as "must stay unbound".

> - **Chords** (`chord.ts`): `Chord.code` is set for position-based chords (digits, any chord with `Alt`, `Shift` with a non-letter, letters with `Mod`/`Ctrl`/`Alt`) and matched on `event.code` with exact modifiers; `matchesByCode(chord)` tells the engine which kind a chord is. `toChord` no longer rejects `Shift+<symbol>` or `Alt+<symbol>` (SPEC-005 E3 changed); it throws only for a character with no known physical key. > - **Property commands** (`command-menu/sources/properties.ts`): `PropertyCommand` (picker or run, `appliesTo` `issue`/`issues`, `operation` default `issue.update`, `refs`, `available`, `destructive`) and `propertySource(registry, definitions)`, registered in `CommandMenuProvider` from `PROPERTY_COMMANDS` in `features/commands.ts` (empty until S6). A command is hidden while its operation is not in the registry. `ui.available(target, store)` is `OperationUi.available` (`packages/operations/src/ui.ts`; `store` is `unknown` because `operations` cannot import `sync-client`; the predicate narrows it); `isAvailableHere` in `sources/operations.ts` applies it for operation and property commands, and a throwing predicate hides the command.

## 3. Migration & rollback
One migration, in S5 (next migration number): the `drafts` table with its partial unique indexes. S1, S2, S3, S4, S6, S7a and S7b have none. Before release, a rollback is a revert of the slice plus dropping `drafts` (nothing else refers to it: no foreign keys, by design). After release the migration is forward-only (the table stays). Draft rows hold only the owner's data, so keeping the table after a code rollback is harmless; an unknown synced model on the client is handled by the schema hash and resync (SPEC-002), so a rollback that removes the `Draft` model forces a resync, which is allowed. The shortcut and UI slices are code only and revert freely.

## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| The engine change (S1) breaks the existing M0 shortcuts, especially AZERTY `Mod+,` (SPEC-005 E3) | Keep `event.key` first. Table tests per layout in S1, run with the existing M0 tests. The M0 bindings stay unchanged in the same test file. |
| A text-editing chord without `whileTyping: false` deletes an issue (⌘⌫ in the title) | The registry refuses to load it (AC-9), and E16 has its own test. `Mod+Backspace` and `Mod+Z` are the only destructive ones. |
| Browser keys win (`Mod+Shift+D`, `Ctrl+L`, `Ctrl+M`, `Ctrl+Shift+I`, `Ctrl+Shift+1…9`) | Mac-only bindings use `platform: 'mac'`. The S7b hand check decides the rest (SPEC-012 D21), and each command stays in `Mod+K`. |
| Virtualised list loses keyboard focus, or re-sorts under the user | The focused row is pinned mounted. The focus model is a pure module with property tests. Live deltas re-sort without moving focus (E1). |
| 10,000-row scroll misses 60 fps | Arithmetic window, fixed heights, no measuring in render, memoised rows. Perf is held, so S7b checks by hand and records the number. |
| The page slice (S4) is blocked by PLAN-011 S6 and PLAN-013 S2, on the critical path to M1 | S1, S2 and S3 do not wait. S4 can start against stubs of the content hooks (typed by PLAN-011 S5b), then switch. Slots let PLAN-013 S5, PLAN-014 S5 and PLAN-015 S4 land after. |
| Drafts leak, or reveal a private team | The model's groups are only `user:<id>`, no foreign keys, `teamId` and `issueId` are never resolved, and the leak test (not held) is mutation-checked. |
| Draft saves flood the queue while typing a comment | 500 ms debounce per key and one upsert per key; the 50-draft cap is server-side. |
| Two plans build the same piece (slug, route, delete flow) | Each has one owner: `issueSlug`, the issue route and `issue-url.ts` are PLAN-011 S4's; the read-only frame and the delete flow are this plan's (S4, S6); restore, purge and the archive page are PLAN-015 S4's. |
| The composer's pickers and the page's pickers drift apart | One `picker-options.ts` and one `PropertyPicker` component, used by the page, rows, composer and menu. |
| Sign-out deletes unsent changes, or a blocked delete leaves the replica (Q3) | The dialog warns before discarding a non-empty queue; other tabs close their database on the session-end signal; `sign-out.test.ts` checks the database is gone with fake-indexeddb. Drafts are on the server, so nothing else is lost. |
| A non-member team's list or a linked issue hangs on "Loading…" | `useTeamLoadState` reports `offline` when the socket is down; the loader falls back to "Available when online"; both have unit tests with the fake hub. |
